# S39 回复留存和用量记账

这一轮补上了测试系统的“收件与记账”部分：先把服务商返回的原始内容留在本地，再检查格式、用量和回答。**557 项测试全部通过，其中新增 42 项**；模拟连接已走完 816 步首轮流程，以及包含可选控制题复查的 504 步确认流程。没有读取密钥、调用模型、改账户，也没有新增病例或实测成绩。

## 出错时也要留下可核对的记录

[回复留存组件](../benchmark/transport_s39.py)会先记录本次尝试和实际请求内容，再建立测试连接。收到的字节分段保存后才解析 JSON。即使遇到限流、服务商错误、跳转、格式错误、型号不符、回答截断或人工中断，也不会自动重试。只收到半截回复，就明确保留半截，不能据此断言服务商没做完、没收费。

网络目标固定为三家服务商的接口，不跟随跳转。当前没有启用真实连接器，也不读取环境文件；测试只使用固定的假密钥。日志目录和文件仅允许本机所有者访问，元数据不记录认证头或异常原文。原始回复可能含有推理内容，仍须留在本地；判分只使用可见回答。回复过大时只保存有明确标记的前缀；本地超时也不等于服务商侧停止计费。

测试已经把这个组件接到原来的 S38 调度和校验上，控制题检查、阶段隔离、六款候选、两名裁判、重复判分分开报告等规则都没有改变。但这还不是可启动的付费运行器：真实入口会直接拒绝调用，后续仍需接好 HTTPS 和授权检查。

## “估算费用”和“实际返回的收费”分开看

[记账模块](../benchmark/usage_s39.py)按三种情况处理，不把所有数字混成一个总账单：

| 情况 | 怎样记录 |
|---|---|
| Grok 返回收费字段 | 原样保留整数计费单位，不用 token 数重新猜一次 |
| Gemini、MiniMax 返回完整用量 | 按既定短上下文标准价估算，单列为估算值，不假定缓存优惠 |
| 用量缺失、格式不符或超出支持范围 | 费用记为未知并停止，绝不当作零费用 |

[xAI 的说明](https://docs.x.ai/developers/cost-tracking)给出了每次请求的 `cost_in_usd_ticks`，一美元对应 100 亿个计费单位，返回值已包含适用优惠及 token／工具收费。本项目仍不允许工具调用。这个字段能帮助事后核账，却不能提前限制下一次请求花多少钱。

[Gemini 的 Interactions 接口](https://ai.google.dev/api/interactions-api)把回答和思考 token 分开列出，估算时两者都要算；总数对不上就停止。[MiniMax](https://platform.minimax.io/docs/api-reference/text-chat-openai)的 completion 总数只计一次，不能再叠加一遍推理数量。这两家的计算仍是未扣缓存优惠的估算，不代表最终账单。

如果回答校验失败，但此前已拿到有效用量，该用量仍会保留。断网或型号不符时，汇总费用维持未知，原始证据有多少留多少。报告会分别显示服务商返回的收费小计、token 估算小计，以及还有多少次费用不明；不会把缺失项悄悄抹掉。

## 下一步先明确费用控制的口径

现在真正需要确定的是：预算必须是“绝不超过的硬上限”，还是可以接受“看到累计费用到线后，不再发下一次请求”。前者需要核实单次请求的最高费用或服务商侧控制；后者容易实现，但最后一笔可能超线，失败请求也可能已经收费。之前首轮 $55、确认阶段 $35 仍只是提议，不是已生效的硬限制。这次没有代替你选择，也没有取得付费运行授权。

口径确定后，再把真实 HTTPS 连接器接入固定流程，在获批的调用范围内验证账户和型号可用性，确认各家的生成参数，冻结传输内容、调用次数和费用授权。确认阶段仍单独批准。一般的“继续”或更换 MiniMax 名单，不等于批准这批付费请求。

候选仍为 Gemini 3.5 Flash-Lite／3.8 Flash、Grok 4.6／4.7、MiniMax M3.1 Flash／M3。计分规则不变，约 80 指固定模型组整体均分，不会为达到目标而强行调整成绩。开发集保持 125 族／250 个语言版本，另有 3 族／6 个版本的新确认题；获批校准集和隐藏 Gold 都为零。专家审核继续后置，H129 补充进交接清单；西安资料、购买资产和密钥不上传。

检查命令：`python3 -m benchmark.transport_s39`；全量回归：`python3 -m unittest discover -s tests -q`。[策略与依据](../config/transport_s39_v1.json)、[冻结记录](../config/transport_s39_frozen_v1.json)、[审计摘要](../data/audit/s39_capture_summary.json)。S26–S38 的冻结文件全部保留原样。
