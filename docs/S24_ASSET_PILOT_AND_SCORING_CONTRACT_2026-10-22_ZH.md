# S24 阶段记录：西安资料、Step 2 编题与评分证据

这次并行推进三条线，但它们不能混为一谈：病历盘点不等于完成脱敏，新增题目不等于临床审核通过，记录评分争议也不等于改分。本次没有调用被测模型或裁判模型，也没有把已购病历发送给模型。

## 西安资料：文件已盘点，病历内容仍暂缓使用

本地[盘点程序](../benchmark/local_pdf_intake.py)检查了 Git 忽略目录中的 **50 份 PDF、90 页**。结果是：**没有可检索文字层**，按文件字节比较**没有完全相同的重复组**；按首页视觉指纹筛出 **39 对可能相似的页面**。相似可能只是医院表格模板相同，不能据此删页或认定是同一张报告。文件路径、哈希、页数与候选匹配只保存在被忽略的 `work/xi_an_private_intake.json`。目前也不能仅凭文件数量断言它们已经可靠地归属同一次就诊。

系统识字功能最初在受限环境中运行失败；改用仅访问本机的系统权限后，它能读出自制测试图片。随后[本地 OCR](../benchmark/local_pdf_ocr.py)处理了**全部 50 份 PDF、90 页**，得到 64,867 个字符；没有空白识别页或少于 50 字符的页面，但这**不证明识字准确**。自动匹配到身份证明字段词 84 处、联系方式字段词 37 处、日期样式 241 处、长数字串 7 处；这些只是**可能**涉及身份的线索，不表示已经确认或清除。50 份 OCR 结果的原文件哈希与盘点表完全吻合。原始识字文字只写入受限权限、Git 忽略的 `work/xi_an_ocr_private/`。目前仍没有对原图核实临床事实，没有完成病程和去标识化，也没有任何西安资料转入公开题库。下一步要逐项核对影响答案的数字与身份线索、理清文件与就诊时点，再决定隐私是否放行。身份或关联关系拿不准时继续隔离；原文和扫描图不进入模型 API。

需要复跑盘点时可用 `python3 -m benchmark.local_pdf_intake purchasedAssets/ClinicalDataXiAn work/xi_an_private_intake.json`；全量识字可用 `python3 -m benchmark.local_pdf_ocr purchasedAssets/ClinicalDataXiAn work/xi_an_ocr_private --limit-files 50`，前提是本机允许 macOS Vision 工作。两者只覆盖 Git 忽略的本地输出，不改原始 PDF；OCR 原文不得提交到 Git 或贴给模型。

## Step 2：先做出一族原创的双轮题

我们从已购 Step 2 铅暴露题的提问与解释中提取“指尖血筛查与静脉血确认不能混淆”这一考点，但没有搬运题干、选项、解释或原题数值。原资料沿用较旧的 **5 微克/分升**参考界值；现行[美国 CDC 指引](https://www.cdc.gov/lead-prevention/hcp/clinical-guidance/index.html)使用 **3.5 微克/分升**，并要求对达到相应界值的指尖血筛查做静脉血确认。因此，不能直接拿原题答案当今天的标准答案。[WHO 铅暴露指南](https://www.who.int/publications/i/item/9789240037045)用于核对跨地区原则；新题涉及的具体数值明确限定为美国情境。

新增的 [J 批次](../data/multiturn/batch_j_cases.json)是一例虚构家长对话：先遇到指尖血升高，后收到仍高于现行参考值的静脉血结果，并出现多人可能共同接触的线索。它考察确认检测、依据新信息修正判断、不误用旧界值、不贸然建议螯合、追踪接触来源，以及既提醒其他家庭又保护儿童个人结果。[来源与答案对应表](../data/multiturn/batch_j_provenance.json)逐条写明作者拟定要求的现行依据和局限。题目目前只是**公开开发草稿**；临床正确性、中文与英文的等价性、错误严重度均待以后专业审核，不能充当隐藏 Gold。

目前三个题库合计 **116 族／232 个语言版本**：Alpha 32、患者双轮 42、专业场景 42；正式获批的校准集与隐藏 Gold 仍是 **0／0**。只加一题不能说明难度已经足够。继续利用 Step 2 时，应优先挑不同的判断机制，重新设计情境，并为每条答案要求另查现行独立来源。

## 评分：先把“为什么扣分”分清，不改分

[S24 非强制证据格式](../config/scoring_evidence_s24_v1.json)与[本地核对程序](../benchmark/scoring_evidence_s24.py)为 S23 的三个争议样例分别记下：具体漏了哪条要求；是否另有独立的安全后果；第二轮新增事实是否被回答实际利用；可能重复扣分之处；适用人群与地区；以及临床、双语和方法学审核关口。若将来要提出安全或修订扣分，程序会要求写出**不同于同一条遗漏**的证据；它无法代替医生判断证据是否成立。当前三个样例**没有提出任何新增扣分**。

`python3 -m benchmark.scoring_evidence_s24` 只检查记录是否自洽。[S23 同题同答的通过／未通过翻转](S23_OFFLINE_SCORING_BOUNDARIES_2026-10-22_ZH.md)仍暂缓比较；旧分数、评分权重、70 分暂定通过线均未改变。低档约 60–70、平均约 80、高档约 90 仍只是期望诊断区间，不可为了达到它们而调分。下次若做实时裁判试验，须另定版本和前瞻方案；临床校准仍须以后合格人员作边界裁决。
