# 八族试验的模拟运行与报告流程

八个新病例的流程已经接通：**按顺序作答和评判、保存请求及回复、从记录重新核对结果、生成逐病例报告**。完整演练能够走完拟议的 480 次请求，形成 64 段首评和 64 段复评记录。这里的回复及用量都是人为构造的测试数据，不是 Gemini 或 MiniMax 的真实表现；没有连接供应商，也没有产生 API 费用或新的临床成绩。

[公开演练摘要](../data/audit/s61_standalone_rehearsal.json)只保存数量和协议哈希，不发布模拟分数。题目、答案标签、参考对照和 S60 的输入版本均未改动；选了哪些病例、为什么这样分组，仍见[八族试验方案](S60_STANDALONE_PILOT_ZH.md)。

## 现在能走通哪些环节

演练按既定顺序处理：64 次对照首评、32 次对照复评、128 次候选作答、128 次候选答案首评、128 次复评。两个 Gemini 版本和两个 MiniMax 版本都保留。作答参数沿用此前的可见文本对话方式，裁判沿用 S56 的证据要求；旧价格仅用于测试记账逻辑，不能当作下一次运行的报价。

追问必须接在同一模型、同一对话的首答之后。模型身份、病例版本、首答内容和原请求都有哈希绑定，不能拿另一模型的答案接着问；供应商返回的推理内容也不会偷偷进入下一轮历史。候选模型看不到评分要求或未来追问。首轮裁判只看首轮，追问裁判虽然能看前文，但只判断追问要求。Q 批追问的第四项不会被漏掉。

程序先保存本次尝试和完整请求，再调用内置的模拟连接；收到的数据先落盘，之后才解析。HTTP 失败的正文即使长得像一个合法答案，也不能进入评分。模拟接口不接受密钥或外部连接函数，因此无法发起真实供应商调用。

复评必须使用与首评完全一致的请求字节。每次模拟请求之前都会重查已绑定文件的哈希；文件中途改变，写入器立即停止，不能恢复文件后继续假装没发生过。中断的记录也不能重开、重试或续跑。

## 失败时怎样处理

| 情况 | 本次演练采用的处理方式 |
|---|---|
| HTTP 拒绝、重定向、回复不完整、超时或用量不明 | 全局停止，保留尝试和未知费用，不记为临床零分 |
| 费用可核算，但候选回答无效 | 停止该候选模型后续作答；其他模型和全部报告格仍保留 |
| 费用可核算，但裁判回复无效 | 停止，不补写回复，也不自动重试 |
| 模拟记账达到测试阈值 | 记下最后一次费用后停止；最后一次可能超过阈值 |
| 只有首答，没有有效追问回答 | 保留首答及其单轮判断，整段对话的分数留空 |
| 写文件中断 | 写入器失效，只能读取已有记录检查，不能据此续跑 |

重新读取记录时，程序会重建每次请求、依赖关系、答案、裁判判断、费用和停止状态，并核对保存的正文及哈希。文件变化、链接文件、序号缺口或停止后还有新记录，都会被拒绝。若回复已完整保存、但最终结果文件没写完，可以只读地重新解释这一份回复；不会把它算成第二次尝试，也不会补写文件。尚未确认的尝试继续标为未解决。

这只是对运行记录的独立重读，不是另一位临床裁判。命令行演练会新建临时目录，结束后清理；需要保留的程序化演练记录只能放在被 Git 忽略的 `work/` 或临时目录，不能写入公开病例文件夹。

## 报告能看见什么

64 个预定格不会因为失败或待审而消失。每格分别列出首轮、追问、首评、复评、评分区间和暂定通过状态；复评导致分数或通过状态变化，会单独列出，不取平均掩盖。缺答案或无效判断的整段分数是空值，不是零。

对照报告保留每一轮实际得到的要求状态、错误和独立观察标记。危险示例的预期错误没被识别，或者其他示例被判出错误，都能看到；原样复评的变化也不会被隐藏。程序不把作者预期强行写回结果，更不要求每删一句就必须扣分。

**这次演练的准入条件只检查工程完整性：96 份对照回复必须全部符合结构要求，才继续模拟候选作答。**含义上的分歧会记录下来，但真正联网时的裁判质量门槛尚未确定。因此“演练跑完”不等于可以开始付费，也不等于裁判已经临床可靠。联网门槛必须在看到新成绩前写清楚，不能根据结果临时决定。旧 S58 的门槛和成绩保持原样。

分数计算仍沿用 S36。模拟数值只用于测试算分和报告，公开摘要不包含具体分数、原始回答或裁判解释，也不生成模型总均分或排名。你提出的低档 60–70、平均约 80、高档约 90 继续作为观察目标，不靠修改标签和权重硬凑。

```sh
python3 -m unittest tests.test_standalone_rehearsal_s61 tests.test_standalone_pilot_s60 -q
```

第二条命令只能读取已有 S61 记录，不能续跑。[调度与报告代码](../scripts/standalone_engine_s61.py)、[请求记录及重读代码](../scripts/standalone_rehearsal_s61.py)、[离线政策](../config/standalone_rehearsal_s61_v1.json)均独立于旧实验文件；没有联网或审批入口。

下一步单独实现需要消耗明确授权的联网入口，并准备实际运行协议：预先确定对照质量门槛和技术失败规则，冻结模型参数，核实现有模型和价格，再就明确的发送范围与费用阈值另请你批准。旧额度不能挪用。扩题继续在独立批次推进，不因此回到无休止的单题诊断。

当前仍有 **133 个公开草稿病例族／266 个语言版本**，其中 125／250 已登记、八／16 独立，距至少 500 族还差 367；这次没有新增病例。专家临床及双语审核只是后置，获批校准／Gold 仍为 0／0，西安资料继续留本地。

33 项新增集成测试与原有 18 项 S60 检查合计 **51 项定向测试已通过**；全项目离线回归测试也已通过，共 **1,119 项**。检查覆盖完整运行和重读、不同要求数量、同模型历史、复评分歧、不确定区间、单模型停止、缺失轮次、HTTP／格式／记账失败、阈值超出、中断、输入变化和文件篡改。这说明软件在给定模拟条件下按设计工作，不等于临床准确性已验证。
