# 八族模型测试方案和费用申请

这次已把真正联网测试的入口做好，接下来需要你单独批准一次运行。**目前还没发出付费请求，也没有新模型成绩。**题目仍用 O、P、Q 的八个病例族，不改参考要求、计分公式或历史结果。程序、参数、停止规则和价格记录都绑定在同一份[冻结清单](../config/standalone_live_s62_frozen_v1.json)里。

这轮想回答的是：换到这些更有推理冲突的病例后，模型还会不会频繁拿满分？哪些要求能区分回答？同一答案再评一次，结论是否稳定？它不是正式临床认证，也不产生可信的模型排名。你提出的平均约 80、较低档 60–70、较高档约 90 仍保留作观察目标，不通过改权重或挑结果来凑分。

## 会测试什么

每个病例有中英文两个版本，每个版本包含两轮问答。四个模型各做一遍，一共 64 段对话。题目范围见[八族病例选择](S60_STANDALONE_PILOT_ZH.md)。

| 先后顺序 | 最多请求数 | 做什么 |
|---|---:|---|
| 对照答案首评 | 64 | 用已经写好的初始、安全、不完整及危险回答检查评判表现 |
| 对照答案复评 | 32 | 原样重评初始和不完整的后续回答 |
| 四个模型作答 | 128 | 每个语言版本分别回答两轮 |
| 模型答案首评 | 128 | 初始轮、后续轮分开判断 |
| 模型答案复评 | 128 | 对同一份已保存答案再评一次，不重新生成答案 |
| 合计 | **480** | 最多允许的请求数量，不保证一定跑完 |

候选模型是 Gemini 3.5 Flash-Lite、Gemini 3.8 Flash、MiniMax M3.1 Flash 和 MiniMax M3；评判模型仍为 Gemini 3.8 Flash。Grok 本轮不加入，也不因为缺席就记零分。不夹带额外诊断、替补模型或重试。

Google 会收到测试所需的公开合成病例、对照回答、草稿评分要求、评判指令及候选回答。MiniMax 只收到作答指令、病例提问和它自己上一轮的可见回答。西安记录、购买的原始资料和私人临床记录都不外发。

## 先过对照关，再让模型做题

96 份对照回复必须全部有效，然后同时满足三条条件，才开始候选模型作答：

- 16 个预先指定的危险错误都被识别出来。
- 安全回答和共用的初始回答中，没有被判出关键错误；初始轮的复评也计入。
- 32 组重复评判中，至少 **31 组**的逐项判断及错误清单完全一致。

这三条是本轮预先写明的筛查规则，不是临床专家认可的质量标准。31/32 的意思是这小批样本最多容许一组不同，不能拿来宣称可靠性已有保证。如果没通过，就停在对照阶段，保留分歧。不能直接认定一定是评判模型出错，更不能为了通过而悄悄改答案标签。

不完整回答如果被发现关键错误，会照实保留；这里没有要求它必须拿多少分，也没有强制“安全高于不完整、不完整高于危险”的总分排序。安全性和修正能力的额外观察仍可查看，但不会暗中增加其他放行条件。即使过关，八族的临床及双语审核状态也不改变。

## 参数和遇到失败时的处理

沿用上一轮离线演练的请求内容：候选输出上限 8,192 tokens；Gemini 使用中等推理强度和标准服务。MiniMax 开启自适应推理，M3.1 Flash 使用 `max`、不发送它不支持的服务档位字段，M3 则明确请求标准档。评判输出上限为 32,768 tokens，使用中等推理强度、标准服务、S56 引用要求和原有 S36 算法。本轮不取消输出限制。第二轮只带回上一轮的可见文字，不带供应商内部推理状态；这是本项目选定的对话方式，不代表测试了各家最完整的原生状态接口。

程序一次只发一个请求。HTTP 拒绝、费用或送达情况不明、实际模型身份不符，都会停止整轮。不会自动重试、补发修复、换模型，或中断后接着跑。能确认费用但候选答案无效时，只关闭那个候选模型，其余模型仍可继续。第二轮失败时，第一轮已有答案仍可保留和判分，但整段对话不填总分，更不补成零分。

对照回复无效，或者评判发生非格式类失败，立即停止。候选答案判分阶段，前两次“响应完整、费用明确、只是格式不合格”的回复保留为缺失，其余独立任务可继续；**第三次就停止**。首评和复评合并计数，失败的首评不会靠原定复评来补救。达到费用停止线后不再发下一条，但最后一条请求可能让费用略超线。

## 费用怎么估

2026 年 10 月 27 日核对了两家的公开模型名单和价格，没有测试账户权限或余额。下表单位是美元／百万 tokens，Gemini 的输出费用包含推理 tokens。[Google 价格](https://ai.google.dev/gemini-api/docs/pricing)、[Google 模型名单](https://ai.google.dev/gemini-api/docs/interactions-overview)、[MiniMax 价格](https://platform.minimax.io/docs/pricing/overview)、[MiniMax 模型与参数说明](https://platform.minimax.io/docs/api-reference/text-openai-api)。

| 模型 | 输入 | 输出 |
|---|---:|---:|
| Gemini 3.5 Flash-Lite | $0.30 | $2.50 |
| Gemini 3.8 Flash | $0.75 | $3.75 |
| MiniMax M3.1 Flash | $0.15 | $0.60 |
| MiniMax M3 标准档 | $0.30 | $1.20 |

Gemini 3.8 的优惠价截至 2026 年 12 月 31 日。M3 在请求标准档后如果仍返回含义未核实的 `default`，费用监测继续按较高的短上下文优先档 $0.45／$1.80 计算；这是保守监测办法，不是确认供应商实际用了优先档。估算不扣缓存折扣，也不使用工具。每次发请求时，价格和模型核查记录必须在 24 小时以内；若需要刷新协议，冻结清单和授权也必须重新对应。

**申请的停止线是 20 美元，接受最后一条请求可能超出的情况。**为了帮助判断数量级，假设每次请求都用 4,000 输入及 4,000 计费输出 tokens，480 次约为 **7.6544 美元**；若两项都变成 8,000，则约为 **15.3088 美元**。两个例子都用了 M3 的较高监测价。这不是实测预测或最高费用；如果回答和推理更长，可能没跑完就触及停止线。无法确认的费用不会当作零，而是停下来保留为待核对。

## 本地怎么运行

先明确批准本轮题目、向哪两家发送什么内容、最多 480 次请求、20 美元停止线及上述规则。操作人员再把这次真实批准记入本地私有文件，绑定协议哈希和唯一运行编号。授权最长有效 24 小时，读取密钥和联网之前就被消耗；失败后删掉结果也不能恢复额度。这是可信本地操作人员的记录机制，不是防御同一系统账号恶意操作的身份认证系统。

```sh
python3 -m scripts.standalone_live_s62 proposal
python3 -m scripts.standalone_live_s62 snapshot
python3 -m scripts.standalone_live_s62 preflight --freeze config/standalone_live_s62_frozen_v1.json --approval work/s62-approvals/OWNER_APPROVAL.json
python3 -m scripts.standalone_live_s62 run --freeze config/standalone_live_s62_frozen_v1.json --approval work/s62-approvals/OWNER_APPROVAL.json
python3 -m scripts.standalone_live_s62 replay --directory /absolute/project/path/work/s62-runs/RUN_UUID
```

前两个命令查看方案，`preflight` 只检查授权，`replay` 只核对旧记录；它们都不调用模型。只有 `run` 在授权通过后才读取密钥。程序没有自动生成批准、重试或恢复运行的命令。日志和授权凭据放在不提交 Git 的 `work/`，密钥仍在 `.env.local`。只读核对会从收到的原始回复重建结果，识别中断和篡改，不修改记录；授权过期后仍可按原批准时间检查历史运行。
