# 在哪里找病例和答案，以及下一批怎么扩充

目前公开草稿共有 **133 个不同病例族**：125 个已登记到开发集，另外 8 个属于尚未登记的 O、P、Q 批次。每个病例族各有一份中英文版本，不能按两道独立病例计算。新增目录只是把现有内容整理到同一个入口，不会自动把 O、P、Q 加入测试，也不会改动旧实验。校准候选、确认集和西安私人病历不计入这 133 个。

## 查找病例和答案

在项目目录运行：

```sh
python3 -m scripts.authoring_catalog --summary
python3 -m scripts.authoring_catalog
```

第一条显示数量；第二条逐项列出病例编号、所属方向、是否已登记、文件位置、中英文版本、内容哈希、来源和答案字段位置。新增的[目录配置](../config/authoring_catalog_v1.json)负责列出独立草稿批次；哪些数据属于已登记开发集，仍以原有的[基准配置](../config/benchmark.json)为准。

| 病例方向 | 现有数量 | 去哪里看答案标准 |
|---|---:|---|
| Alpha 单轮问答 | 32 个已登记病例族 | JSONL 中每条病例的 `reference_answer`、`critical_requirements`、`critical_errors` |
| 患者多轮对话 | 51 个已登记病例族 | 每一轮的必答要求和严重错误；真正评分时，还必须明确选择并冻结与病例版本匹配的评分边界 |
| 专业临床任务 | 42 个已登记病例族 | 各语言版本的 `reference_elements` 和 `critical_errors`；暂未开放专业任务评分 |
| O、P、Q 独立草稿 | 8 个未登记病例族 | 病例、评分边界、参考回答、对照回答和来源映射分别保存，见下方链接 |

[O 批次](BATCH_O_STANDALONE_ZH.md)讨论液体负荷与肾功能之间的取舍，以及营养补充后的电解质变化。[P 批次](S54_LIVE_ADMISSION_AND_BATCH_P_ZH.md)讨论血小板计数不可靠、诊室与家中血压不一致。这些答案目前都是作者草稿，不代表已有临床专家认可；它们也没有自动进入当前评分实验。

## 下一批具体做什么

长期目标仍是 **至少 500 个不同病例族**。按现有公开草稿计算，还需要增加 367 个。翻译、改写措辞、同一病例的强弱回答对照，都不算新增病例。数量达标和可以对外发布，是两件不同的事。

[Q 批次](S59_BATCH_Q_CASE_EXPANSION_ZH.md)已经完成原计划中的四个新问题。[S60](S60_STANDALONE_PILOT_ZH.md)现已把 O／P／Q 八族绑定成离线试验方案，但没有自动登记或增加族数。接着用模拟回复接通试验流程，扩题继续另批推进。结合本轮结果选缺口，但不要回头改动已经测过的病例。重点放在多种解释之间的判断、随病程更新结论、治疗利弊冲突，以及新证据如何改变行动。患者的问题不要提前点破正确结论；同时保留需要克制处理的情境，避免模型只要一律建议急诊就能得高分。

每个病例交付一套完整材料：自然的中英文对话、分轮次的预期行为、可接受的其他答法、拟定严重错误、参考回答及有控制的遗漏示例，并逐项说明答案要求由哪条公开证据支持。真实发表病例用于提取临床机制和决策过程，不直接充当新病例的标准答案。来源本身不能解决的问题、语言歧义和临床不确定性，边写边记入后续专家审阅清单。公开草稿不带患者身份信息，也不复制原始病历图片。

新批次进入实验前，先核对是否与已有开发集或预留集重复，再检查病例与答案的版本绑定，并单独冻结实验材料。不修改旧实验，也不为了让低档模型落在 60–70 分、平均约 80 分、高档约 90 分而倒推标签。这些数字仍是观察目标。临床和双语专家审阅可以后置，但没有取消。

目录检查只证明数量、编号、语言配对和文件位置等结构正确，不证明病例医学正确、足够困难或可以发布。

## 原定四族扩充已经写成草稿

[S59／Q 批次](S59_BATCH_Q_CASE_EXPANSION_ZH.md)新增四个方向：补铁后的低磷问题、术后炎症性伤口与感染、高钙诊断未清时的手术决策，以及混合试验即刻纠正但出血加重。八份中英对话配有 28 个要求位置、八份首轮参考回答和 24 份完整／删项／危险追问示例。

原来这里只列了两条线索，现在它们和另外两条公开病例机制都已写成完整草稿。[题目](../data/multiturn/batch_q_cases.json)、[评分边界](../config/multiturn_criterion_anchors_batch_q_v1.json)、[参考回答](../data/multiturn/batch_q_contrasts_v1.json)和[来源映射](../data/multiturn/batch_q_provenance.json)仍在默认名单之外；H149–H152 记录专家需核查的问题。本次不产生分数，也不能宣称已经证明题目更难。

运行 `python3 -m scripts.audit_batch_q` 可以复查结构、版本和公开开发／预留题中的报告标识重合情况。语义上的相关题仍需人工分组。S60 采用 O 的 S52 衍生版，而本目录仍指向原编写文件；版本变化不增加病例族数。实际运行的参数、门槛、最新费用依据和新授权仍待准备，不能借新草稿重新打开 S58。
