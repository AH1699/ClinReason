# 评分边界小实验和新题答案对照

## 现在可以进入哪一步

S30 的程序、裁判提示词、输出格式、题目、答案、规则和调用顺序已经冻结，接下来需要确认是否运行这 **24 次以内的外部调用**。目前 S30 真实调用为零，不能沿用上次两次连接诊断的同意继续花额度。

这次只检查鼻窦症状题中的两条规则：简短但明确的病程推理是否得到相应认可，以及没有交代后续就医条件时怎样分档。裁判仍是 Gemini 3.8 Flash 和 Grok 4.7。不让被测模型生成答案，也不给总分。S29 的 65 分和另一次不确定判断保留原样，不拿新规则重算旧结果。

## 会发出去什么

服务商收到的是中英文合成对话、事先编写的回答、两条目标要求及评分边界、通用档位定义和裁判指令。不会附带“这是完整答案还是部分答案”、作者预期档位、过去分数或希望模型得多少分。

**不发送西安病历、已购 Step 2 原文、个人资料或包含密钥的评测正文。**密钥仅用于请求认证；两家服务商都可能按 API 用量计费。新补的 N 批次答案也不在本次外发范围内。

| 环节 | 怎么组成 | 最多调用次数 | 判定的要求数 |
|---|---|---:|---:|
| 首次判断 | 五种回答 × 中英文 × 两个裁判 | 20 | 40 |
| 重复判断 | 原来那份部分回答 × 中英文 × 两个裁判 | 4 | 8 |
| 合计 | 不重试，不调用被测模型 | 24 | 48 |

其中四种回答预先写了作者判断，合计 **32 个首判档位**；模糊地说“照之前安排”的回答没有预设档位，留下 **8 个探索性判断**。复判另看 **8 个档位**是否一致。这些不是 48 个独立病例，也不是专家批准的标准答案。

先按材料内容指纹排序，同一材料先 Gemini、后 Grok；20 次首判完成后，再重复指定部分答案。复判不改正文，也不告诉裁判这是复判。每次 socket 超时预先设为 240 秒，采样沿用服务商默认值；不能据此保证整个实验的总时间或完全可重复。

## 在看到结果前，先定好规矩

每份结果只能包含第 1、3 条要求，按这个顺序返回档位、依据和理由。判为“满足／部分满足”必须引用更新轮回答里的原文；引用首轮或用户的话不算有效回答证据。按照本实验的设定，首轮可以提供背景，却不能自动填补更新轮漏说的内容。这个设定是否适合真实连续对话，仍留给 H117 的后续审核。

连接错误、输出不合格式或模型名不符，立即停止并保留此前结果，不修复重试、不续跑。“不确定”本身是有效档位；裁判与作者意见不同也要保留，不能因此提前结束或再抽一次直到一致。程序发送前先记下尝试，收到服务商 JSON 后先保存再校验，错误日志只记录限定字段，原始回复只留本地忽略目录。

进入后续完整评分实验设计，需要同时满足：24 次都有有效结果、已知样例 **32／32** 与事先的作者预期一致、复判 **8／8** 档位不变。模糊样例单独报告，不根据结果补写“正确答案”。即使全部通过，也只支持设计下一轮完整评分与复评，既不自动增加调用权限，也不能宣称临床校准完成。未通过就保留限制；若再修改规则，需要另起版本，不能在本次额度内反复尝试。

## 怎样核验和运行

[冻结清单](../config/s30_boundary_frozen_v1.json)绑定了 30 个文件、十份裁判材料、调用顺序和输出结构。协议指纹为：

```text
23161d0b53e3cb3604ee4d2e294bda4284f7c765e881702e3a91d7676b5de4f6
```

下面这些命令只做本地检查，不产生 API 费用：

```sh
python3 -m benchmark.boundary_s30 plan
python3 -m benchmark.batch_n_packet_audit
python3 -m unittest discover -s tests
```

先提交冻结版本，并取得对本次外发内容和调用上限的明确同意，才可在新的本地目录运行一次：

```sh
python3 -m benchmark.boundary_s30 run --output work/s30_boundary_2026-10-23 --max-calls 24 --approved-protocol-sha256 23161d0b53e3cb3604ee4d2e294bda4284f7c765e881702e3a91d7676b5de4f6
python3 -m benchmark.boundary_s30 audit --output work/s30_boundary_2026-10-23
```

参数里的协议指纹用于避免跑错版本，不等于程序能够自动证明用户已经同意。缺少或写错指纹、调用上限不是 24、输出目录已存在，都会在读取密钥前拒绝。中断的实验不能续跑。旧的 `boundary_s30_draft` 命令只描述原先离线草案；现在请用 `boundary_s30 plan` 看冻结程序的准备状态。

## N 批次这轮补齐了什么

现有水杨酸盐题补齐了[七条评分边界](../config/multiturn_criterion_anchors_batch_n_v1.json)、两份中英文首轮回答，以及[六份更新轮对照](../data/multiturn/batch_n_contrasts_v1.json)。部分答案只删去“专科评估清除治疗”这一部分，不能因为少说这点就自动认定成三级危险错误。危险答案则明确支持在恶化时离院，并联动替换四段相关内容，避免一边说离院、一边保留马上请急诊处理的自相矛盾建议。

原题和[七条来源位置记录](../data/multiturn/batch_n_provenance.json)没有改变。EXTRIP 支持在浓度之外考虑严重临床表现，但没有替我们规定具体给分档位或错误严重度；这些仍是作者设定。[EXTRIP 原文](https://www.extrip-workgroup.org/salicylates)。用药暴露和酸碱解释的背景见 [Merck 专业参考资料](https://www.merckmanuals.com/professional/injuries-poisoning/poisoning/aspirin-and-other-salicylate-poisoning)。

离线检查核对的是题目指纹、来源位置、中英文删改目标、错误编号和六份不含作者标记的材料，不是临床评分。改了几段文字，也不代表只影响几个独立评分项。这批对照还没有调用裁判，不包含在 S30 里。
