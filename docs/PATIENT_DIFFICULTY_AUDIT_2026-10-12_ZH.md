# 面向患者的难度审计——有限试运行

这只是**开发阶段的诊断**，不是临床评估、模型排名，也不能证明题目达到专家级难度。单轮 Alpha 的 30 个案例家族与独立的双轮 16 家族轨道仍属草案。本次选择双轮轨道，以观察模型在获得新信息后是否修正答复。英文和中文是**同一家族**的配对变体，不是两个独立临床案例。

## 问题与预先确定的样本

现有题目与临时 AI 评审能否显露高分天花板、未修正的答复、安全错误或语言差距？正式 API 调用前，已固定每类两家族，覆盖紧急程度上调，以及避免过度分诊或过度诊断。

| 家族 | 预期测试点 |
|---|---|
| HC-MT-TRIAGE-003 | 原本无症状的严重高血压，随后出现胸部压迫感；是否调整紧急程度。 |
| HC-MT-TRIAGE-005 | 指夹血氧读数看似正常，却出现新的呼吸困难；是否避免锚定单个数字。 |
| HC-MT-MEDSAFE-003 | 抗凝药与布洛芬、目前未出血；是否避免贸然允许用药或一律按急诊处理。 |
| HC-MT-MEDSAFE-005 | 血糖数字单位不明，随后确认低血糖、有症状且准备开车。 |
| HC-MT-REASON-003 | 贫血治疗期间 A1C 变化，但血糖记录未变；是否避免武断推断血糖改善。 |
| HC-MT-REASON-004 | FIT 阳性后家庭复测阴性且就医有障碍；是否仍建议适当随访。 |

这些只是作者设想的测试点，不是经过验证的难度标签。尤其 TRIAGE-003 与 MEDSAFE-005 的既有“部分正确”对照答案，其安全分类仍有争议；见[临床复核交接清单](CLINICAL_REVIEW_HANDOFF_ZH.md)。本次不把它们当作标准答案。

## 复现流程

命令读取本地被 Git 忽略的密钥，产物只写入被忽略的 `work/`。去掉 `--live` 即为不联网的计划检查；再次运行时须改用新的输出文件名，因为命令会拒绝覆盖旧产物。完整候选模型运行包括 12 段对话、24 次 Grok 调用；评审另需 12 次 Gemini 调用。候选模型只看到当前及此前可见对话，不会提前看到标签或后续用户消息。

```bash
python3 -m benchmark.cli generate-grok-multiturn \
  --family-ids HC-MT-TRIAGE-003,HC-MT-TRIAGE-005,HC-MT-MEDSAFE-003,HC-MT-MEDSAFE-005,HC-MT-REASON-003,HC-MT-REASON-004 \
  --limit 12 --output work/difficulty_audit_2026-10-12_grok_answers.jsonl --live
python3 -m benchmark.cli judge-multiturn-gemini \
  --answers work/difficulty_audit_2026-10-12_grok_answers.jsonl \
  --limit 12 --output work/difficulty_audit_2026-10-12_gemini_judgments.jsonl --live
python3 -m benchmark.cli difficulty-audit-multiturn \
  --answers work/difficulty_audit_2026-10-12_grok_answers.jsonl \
  --judgments work/difficulty_audit_2026-10-12_gemini_judgments.jsonl \
  --output work/difficulty_audit_2026-10-12_report.json
```

审计命令会核对案例哈希、两份运行清单、评分规则哈希、模型身份、候选答案与评审案例集合、重新计算的分数，以及每个家族的中英文是否齐全。报告包括分数分布、90 分及以上与满分数量、首轮/更新轮/修正分数、各阶段严重错误及语言配对差距。这些只是**单一 AI 评审输出的描述**，任何分数界线都不是临床合格标准。摘要报告不含原始题目、候选答案或评审理由。

## 试运行观察——当地时间 2026 年 10 月 12 日

Grok 4.7 完成全部 12 段选定对话（24 次候选模型调用）；Gemini 3.8 Flash 完成 12 次结构化评审。审计核对两份清单并重新计算全部分数。原始回答、评审理由及机器可读报告留在被 Git 忽略的 `work/`，不进入仓库。

| 诊断项 | 观察结果 |
|---|---:|
| 配对家族／对话 | 6／12 |
| 临时总分恰好 100 | 12／12 |
| 首轮、更新轮及修正分数恰好 100 | 每个分项均为 12／12 |
| 评审标出的关键错误／硬性失败 | 0／0 |
| 英中配对分差 | 六个家族全部为 0 |
| AI 评审主动请求人工复核 | 0／12 |

三个类别各有四段获临时满分。对分诊、用药安全及 FIT 随访的部分候选回答与评审理由抽查，看到候选回答覆盖了*草案所列要求*；这**不是**独立医学评估。AI 理由有时称回答“临床合理”，且从未主动请求人工复核，但它的标记不能解除强制的案例及语言审核。零分差也不能证明译文语义等价。

**解读：** 在这个事先固定的样本里，这一组候选模型和 AI 评审没有产生分数区分度。这是具体的满分天花板现象，不证明题目客观上容易、候选模型临床可靠，或评审必然正确。先前五组英文受控的“较好＞部分正确＞明显不安全”对照能使评审给出分层，但中间档的安全分类仍待确认。下一轮应加入另一个独立能力层级的候选模型或导入其回答，重复运行重点案例，再决定是否改评分规则或大规模增题。今后还须核查任何表面区分能否通过临床及双语人员裁决。

## 解读与下一道关口

一个候选模型加一个未经校准的评审，可以指出疑似高分天花板和待核查案例；不能测出跨模型区分度、重复运行稳定性或临床正确性。下一轮需加入至少另一个独立能力层级的候选模型（或导入其回答），对重点案例重复运行，并用合格临床及双语评审意见盲法校准评审，同时划分开发集与保留集。统计单位应是家族，不能把译文重复计为独立案例。后续应根据真实失败模式修改案例，而不只是加长题目。面向临床专业人员的能力测试应另建轨道。

任务针对性、对照测试和人工校准的设计参考[OpenAI 官方评估指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)；这不表示 OpenAI 认可这些案例或评审结果。

## 同一答案的评审重复性补充

相同的 12 条已保存候选答案，由 Gemini 3.8 Flash 使用同一指令和量表重新评分。`compare-multiturn-judges` 核验不同运行时间、相同模型/指令/量表身份、两份清单、完整英中配对、内容哈希及分数重算。结果：**12 条门控分数均未改变**，初轮/更新/修正分数也均未改变；关键错误、硬失败和评审请求人工审核的标记没有翻转。比较产物仍被忽略于 `work/`。这不衡量候选模型的不确定性，不能发现一贯犯错的评审，也不能证明量表的临床有效性。D 批次及尚未解决的对照见[独立记录](MULTITURN_BATCH_D_2026-10-12_ZH.md)。

这些旧答案生成后才把 D 批次加入默认配置。重放历史审计时需给 `compare-multiturn-judges` 或 `difficulty-audit-multiturn` 重复传入 `--cases-path data/multiturn/pilot_cases.json --cases-path data/multiturn/batch_c_cases.json`；旧候选清单绑定的是原两批合并哈希，直接使用当前三批默认配置应被拒绝。
