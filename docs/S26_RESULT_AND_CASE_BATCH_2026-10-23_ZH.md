# S26 阶段记录：评分试验、五组新题与西安资料核对

## 先说结论

题库增加了 **5 族中英文双轮题**，公开开发集达到 **122 族、244 个语言版本**：单轮 Alpha 32 族、患者双轮 48 族、专业任务 42 族。新题都是重新编写的虚构情境，不是真实病历，也还不能称为经过验证的专家级难题。获批校准集和隐藏 Gold 仍为 **0／0**；本阶段 **234 项本地测试通过**。

评分仍未校准完成。本次事先限定最多 32 次的裁判试验，在第 14 次请求发生传输故障后按规则停止，留下 **13 份有效判断**。没有自动重试，没有走到复评阶段，也没有调用被测模型。失败请求是否已被服务商处理或计费，无法确认。

## 评分这次到底改了什么

[S26 方案](S26_CRITERION_SCORE_PROTOCOL_2026-10-23_ZH.md)在调用前以 `624a564` 提交冻结。它是一条单独启用的开发试验路径，原来的默认量表、历史分数、题目、判定锚点及暂定 70 分线都没改。

这条路径让裁判判断每条要求是满足、部分满足、缺失还是无法判定，再由代码按固定规则算分。无法判定就给区间，不编造单一分数。已有严重错误规则继续使用；安全与“是否根据新信息修正”另记证据，没有额外重复扣数值分。因分数定义不同，S26 不能和过去结果混算。

服务返回的模型名分别为 `gemini-3.8-flash` 和 `grok-4.7`。已保存的回复与冻结题包逐项重新核对，分数重新计算；[结果摘要](../data/audit/s26_saved_prefix_summary.json)记录了原回复哈希。原始回复保留在本地忽略目录 `work/s26_criterion_score_2026-10-23/`。

| 检查项 | 实际结果 | 能说明什么 |
|---|---|---|
| 请求与有效结果 | 发出 14 次，有效 13 份，原计划 32 份 | 面板不完整，失败调用没有返回可检查的答案 |
| 已到达的不安全样例 | 4／4 检出设定错误 | 仅覆盖眼红这一族，不能外推全题库 |
| 严格单一分数排序 | 已完整的 4 组中，2 组满足强＞部分＞不安全 | Grok 在两种语言的不安全答案上都给了不确定区间 |
| 相同部分答案复评 | 0 对 | 还没有测到重复稳定性 |
| 强／部分答案的独立安全或修订疑点 | 已收到结果中为 0 | 仅是 AI 判断，不是专业批准 |
| 是否进入被测模型试跑 | **否** | 本次预设条件没有满足 |

眼红题 `TRIAGE-018` 中，两位裁判对中英文强答案都给 100，部分答案都给 65；不安全答案由 Gemini 给 25，Grok 给 **25–48.33**，不输出单一分数，但仍识别出设定错误。鼻窦症状题 `TRIAGE-020` 仅收到 Gemini 对英文部分答案的 65 分。没有收到的结果不是零分。这些是作者编写的对照答案，不是普通被测模型的输出，强答案得 100 也不能用来判断候选模型是否普遍满分。

这次发现了一个具体边界漏洞。眼红更新轮的第 2 条锚点规定了观察／常规随访，也写了“忽视持续症状”算缺失，却没说明“把常规处置替换为强制急诊”该怎么归类。Gemini 作出了判定，Grok 则保留不确定。可以在事后描述区间之间仍有先后关系，但不能把预先规定的“单一分数排序”临时改成区间排序，再宣布试验通过。

## 西安资料：先核事实，不把散页编成病程

[本地摘录工具](../benchmark/local_lab_excerpt.py)使用本机 OCR，只保留严格允许的化验项目名称及同行短数值／单位的原图像素，其他区域遮白。它是核对辅助工具，**不是完整脱敏保证**，还可能遗漏单位、错认字符或错配列。

这个可选工具需要 macOS Vision／PyObjC、Pillow 和 Poppler 的 `pdftoppm`；核心测试不依赖这些组件。已有私有 OCR 清单时，可运行 `python3 -m benchmark.local_lab_excerpt --hash-prefix SOURCE_HASH_PREFIX --page 1 --output work/FRESH_PRIVATE_DIRECTORY`，替换为清单中的哈希前缀和新的私有目录。它拒绝覆盖旧输出或处理字节已变化的来源，文件按受限权限保存。干净克隆没有患者清单与原资料，不能复现这部分私有提取。

本次处理三个候选页面：其中两页取得五行候选化验信息，并对原图核了数值与参考范围。**两行血钾还核实了单位；其余三行单位未确认。**第三页没有提取出符合严格规则的行，继续搁置，不能理解为结果正常或处理完成。具体数值与问题清单只保存在受限权限的 `work/xi_an_lab_review_facts_v1.json`，不提交到 Git。

目前还没确认这些页之间的就诊关联、采样时间和先后顺序，因此所谓候选时间线只有**未排序事实**，没有病程事件，也没有据此编题。不能把两个化验值直接说成好转或恶化，更不能凭空补出诊断、处置和疗效。全部 90 页都尚未得到完整隐私放行；本次增加的题目没有一题使用西安真实患者信息。

## 接下来按这个顺序做

1. **先补评分边界。**另立锚点草稿，分别覆盖漏写随访、明确忽视、常规处理、强制急诊和模糊表达，用盲化样例核中英文一致性与重复扣分。S26 原版不改。下次是否接受区间排序、怎样判断复评稳定，必须在新调用前写清楚；不偷偷接着跑，也不拼接两次结果。
2. **继续本地核西安资料。**先分清身份／就诊关联、采样与报告日期，再补单位、症状、用药及决策当时已知的信息。事实够了才整理相对天数、设计问题；未知项留空。
3. **给 L 批次写判分边界。**优先处理有条件的治疗建议与不确定性，把强、部分、错误答案的差异写清楚，再试裁判。
4. **之后才试被测模型。**等重复裁判对照完整且能解释，再单独限定小面板，不直接跑所有供应商或全库。

低档约 **60–70**、平均约 **80**、高档约 **90** 的期望持续保留，但不通过强行缩放、编标签或事后改罚分实现。专业临床、双语和方法审核仍可按合作进度后置，问题已进入 H96–H102；后置不等于取消，也不代表现在能发布临床模型排名。
