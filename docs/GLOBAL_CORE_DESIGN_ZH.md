# 全球核心与司法辖区扩展包 v0.2 — 中文

本评测通过组合多个明确范围实现全球覆盖，而不是假设各地医疗系统完全相同。它把普适安全行为与受本地政策约束的临床路径分开评测。

## 1. 三层评测结构

### 全球核心（Global Core）

测试不依赖单一国家医疗系统即可判断的行为：

- 识别广泛认可的危险信号，避免危险延误；
- 在个体化建议前识别缺失信息；
- 避免无依据诊断或自行调整药物；
- 清楚表达不确定性、筛查局限和安全下一步；
- 建议联系适当的**当地**急救、临床或药学服务，而不指定某国号码或机构；
- 在应用指南前识别何时必须知道司法辖区。

机器可读元数据使用：

```json
{
  "benchmark_layer": "global_core",
  "jurisdiction": "global_core"
}
```

`global_core` 表示案例经过有意限制，只测试不依赖司法辖区的行为；它并不表示全球医疗实践完全相同。

### 司法辖区扩展包

测试本地指南、就医路径、药物可获得性、急救入口、专业权限、术语和监管边界。每个扩展包都要明确国家或政策区域、来源层级、语言地区和审核资格。成绩按扩展包分别报告。

### 适应层

测试模型能否正确使用已提供的司法辖区，或在必要但缺失时主动询问。该层可包含只改变医疗系统背景的匹配变体。

## 2. 语言不等于司法辖区

全球核心使用 `language=en` 和 `language=zh-Hans`。`zh-Hans` 表示简体中文书写系统，但不默认中国大陆司法辖区。地区扩展包继续使用这些语言标识，并在 `metadata.locale` 中记录更具体的 BCP 47 值，例如 `zh-Hans-CN` 或 `en-GB`；案例契约仍会单独记录司法辖区。

同一案例族的两个语言变体必须保持相同构念、事实、风险和评分政策。本地化可以提高自然度，但不得静默加入某个医疗系统的假设。

## 3. 结果报告

以下结果必须分别报告：

- 全球核心质量与安全；
- 各司法辖区扩展包；
- 匹配案例族中的语言表现一致性；
- 跨司法辖区适应能力；
- 按语言、类别和司法辖区划分的关键错误率。

除非明确披露组成和权重，否则不得发布单一“全球总分”。模型不能用其他地区的高分抵消某一地区的严重安全失败。

## 4. 来源与审核政策

全球核心应尽量使用国际适用来源，例如 WHO 规范性指导，并把案例范围限制到预期行为不依赖本地路径的程度。全球指导仍需专家审核，也可能需要本地情境化。

司法辖区扩展包必须使用当前本地权威来源，并由熟悉该环境的合格人员审核。如果证据或预期行动在不同司法辖区存在实质差异，该案例必须移出全球核心。

## 5. v0.2 Alpha 计划

1. 在六个类别中起草 30 个双语全球核心案例族。
2. 对每个案例族的两个语言变体分别进行临床和语言审核。
3. 使用裁决后的全球核心标签校准评审模型。
4. 根据目标市场和审核资源选择首批司法辖区扩展包。
5. 至少有两个司法辖区扩展包后，再加入匹配适应案例。
