# S5 blinded calibration reviewer handoff — 2026-10-19

This prepares an **offline, two-phase review assignment** for the ten bilingual prospective patient calibration author drafts. It does not assign a reviewer, collect a clinical decision, promote a case, validate a language translation, or score a model. Approved calibration and hidden Gold remain **0/0**. The separate local hidden candidate is **not** included.

The reproducible exporter is `python3 -m benchmark.calibration_review_packets`. It validates the registered case batches, provenance, case/anchor/contrast hashes and split boundaries before writing three **separate, non-overwriting, Git-ignored local directories**:

| Local directory | Audience and timing | Contents |
|---|---|---|
| `work/calibration_review_phase_a/` | Clinical and bilingual reviewers **first** | Ten anonymized item packets, each with paired EN/ZH prompts, a proposed initial answer, and A/B/C update answers in randomized order; blank rating template and manifest. No family IDs, public source links, criterion labels, intended response classes or case hashes. |
| `work/calibration_review_phase_b/` | Release **only after phase-A ratings are locked** | Matching item IDs with source links, case/provenance limits, exact case hashes, draft critical requirements, criterion anchors, error severity/boundaries and blank adjudication template. It still does not disclose the A/B/C author-intent mapping. |
| `work/calibration_review_internal/` | Coordinator only; **never share with reviewers** | The option-order key and exact case/packet bindings. All three output directories use mode 700 and all files mode 600. These permissions reduce accidental local exposure but are not a secure access-control or sealing system. |

The phase-A and phase-B manifests are bound by SHA-256. The local packet created in this checkpoint has phase-A manifest hash `b83c751d9b98224a4a1c8e3b3f9f698fa96914016095ad6a3505ff1662fb2c8e` and phase-B manifest hash `43394369a60c46aa000d5c7fa7de2691bd0c8234b54e392a398a6b29a72511f7`. A clean Git clone must regenerate its own packet; random item/option order gives a new hash. Existing destinations are never overwritten. Share **only the intended phase directory**, not its parent `work/`.

## Review sequence

1. **Pre-assignment:** verify reviewers' relevant qualifications, scope and conflicts outside this repository; assign specialties and a qualified EN/ZH reviewer. Do not assign an author to independently approve their own material. Explicitly disclose prior exposure to these public draft cases or answer keys. Because the cases are already public, blinding is **procedural, not secrecy**: reviewers must avoid source-code or case-file lookup until phase-A ratings are submitted.
2. **Phase A — independent response assessment:** use the blank `rating_template.json` to evaluate the initial answer and each A/B/C update answer for safety, adequacy, omissions, risk change and reasons. Rank options with ties/uncertainty allowed. Review EN and ZH separately before comparing them. Freeze a dated, content-bound copy of the completed form. No benchmark score or author-intended class is shown.
3. **Phase B — evidence and criterion adjudication:** only after phase A is frozen, release the phase-B folder. Evaluate each public source's scope and case adaptation, every proposed criterion/critical error and its severity, acceptable alternatives, triage jurisdiction, and EN/ZH equivalence. Use `criterion_template.json` to mark accept/revise/reject/needs-specialist separately for each language and request exact changes. The case-specific and protocol queue is [H41–H55](CLINICAL_REVIEW_HANDOFF_EN.md). Preserve disagreements for independent adjudication.
4. **Coordinator-only unblinding:** after both phases are recorded, compare reviewer ordering with the author-intent key. A mismatch is a diagnostic question, not proof that the reviewer or author is wrong. Do not modify scores or select reference model tiers to produce the desired ~60–70/~80/~90 bands. Version changed cases/anchors/responses and regenerate hashes; repeat affected review.

**No approval shortcut:** These templates are *assignment aids*, not records accepted by the current Alpha `data/reviews/` validator. Do not copy blank or filled forms into `data/reviews/` as approvals. A separate approved calibration-review protocol and independent clinical/bilingual adjudication are needed before judge tuning, external clinical claims or a leaderboard. The phase ordering follows [OpenAI evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices) on human feedback and [grader guidance](https://developers.openai.com/api/docs/guides/graders) on testing response ordering against trusted judgments; this project did **not** use OpenAI-hosted evals.
