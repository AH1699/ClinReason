## Settings and interpretation

The S38 payload builder is unchanged. This is a **visible-text-history comparison**, not a comparison of each provider's native reasoning-state continuation.

| Provider | Reasoning and sampling | Requested output limit |
| --- | --- | --- |
| Gemini | Medium thinking; sampling omitted, therefore provider defaults | 8,192 including thought and answer |
| Grok | High reasoning; temperature 0.7, top-p 0.95 | 8,192 visible tokens; reasoning is outside that cap |
| MiniMax | Adaptive thinking; M3.1 Flash explicitly max effort; fixed temperature 1/top-p 0.95 | 8,192 completion tokens |

These settings are not equal-compute budgets. Model names may be mutable aliases; omitted defaults can change. Truncated or incomplete responses stop the run as technical failures, not clinical zeros. No settings are silently enlarged after seeing results. Gemini/M3 use standard service tier where supported; M3.1 omits that unsupported field.

Provider documentation checked for these limits: [Gemini thinking](https://ai.google.dev/gemini-api/docs/thinking), [Grok guidance](https://docs.x.ai/developers/model-capabilities/text/best-practices), [MiniMax completion API](https://platform.minimax.io/docs/api-reference/text-chat-openai). Grok recommends carrying encrypted reasoning between turns; this protocol deliberately retains its predeclared visible-history scope and must not be described as maximum native capability.

The new transport uses certificate/hostname-verifying HTTPS to three fixed hosts, no proxy discovery, redirects, tools or retries. Socket timeout is 900 seconds; elapsed time is checked between body reads against 1,800 seconds. A blocking read can delay that check. Local timeout/termination does not prove remote cancellation. Requests are limited to 1 MiB and saved response prefixes to 8 MiB plus one overflow sentinel byte.

Grok reported billing ticks are kept separate from undiscounted Gemini/MiniMax token estimates. Estimates can differ from final billing; any missing/unreconciled charge stops the run. No automatic retry, quota reuse, new output directory or new approval ID is a substitute for fresh human authorization.

## What the code now enforces

1. Verify the frozen source/config/case/anchor chain and exact 816-row schedule.
2. Require a matching, unexpired, private receipt for this protocol and one run ID.
3. Consume its approval ID durably before reading credentials or opening a connection. Reuse is rejected even if key loading or the first call fails.
4. Recheck protocol hashes and receipt expiry before every new dispatch.
5. Persist admission and payload, then capture raw bytes before parsing, cost accounting and score validation.
6. Retain the final over-threshold response, partial bodies and known charges. Stop on failure without repairs or resubmission.
7. Report fixed-denominator missing-result intervals and separate judge results. Repeats assess stability; they do not enlarge the scoring sample.

A receipt is a local operator record, **not cryptographic evidence of human consent**. The operator must first verify the actual user's authorization. The one-shot ledger applies to this checkout; it is not a defense against a hostile local user modifying code, files or the ledger. Existing symlinks and permissive S41 file permissions are rejected.

Output in `work/s41-runs/<run_id>/`: approval copy, capture attempts/payloads/raw bodies/usage/validated replies, spending admissions/settlements, per-request progress and final `report.json`. A crash may leave only durable partial journals, not a final report. Do not resume it or delete its consumption record. Partial/incomplete CLI runs return a nonzero exit status.
