## 哪些内容会发出去，哪些不会

候选模型收到公开案例题面、回答语言要求，以及它自己上一轮的可见回答。首轮不会提前看到后续题目，也看不到评分标签。

两名评审会收到对应阶段的题目、回答、暂定评分条件、重大错误定义和评分格式。我们不告诉评审候选模型的名字，也不把“优秀／部分／不安全”的对照身份作为答案提示发给它。

**西安就诊资料、采购原始文件、确认阶段独有题目和本地秘密不会放进请求正文。**密钥只用于对应服务的身份认证。Gemini 和 Grok 使用 `store=false`，但这不代表服务商绝不保留任何数据；MiniMax 也受其账户数据政策约束。原始回复、费用记录和结果只保存在本地被 Git 忽略的 `work/` 下，不随项目提交到 GitHub。

## $55 怎么执行

每次只发一笔。收到回复后先记账；累计监测金额达到或超过 $55，就保留这笔结果并停止，不再发下一笔。费用无法核对、接口或格式出错、对照检查失败、授权过期，也都会停止。

这里有两个容易误会的地方：

- $55 **不是账单硬上限**。最后一笔可能超额，目前不能给出这个超额的数值上限；本地超时也不能证明服务商已停止生成或不收费。
- Grok 返回的实际计费字段，与 Gemini／MiniMax 按用量和冻结单价算出的估算金额分开保存。监测值不等于最终账单，也管不到账户里的其他任务。

停止后不能自动换个目录重跑、把剩余额度当成新额度，或自己生成新的授权 ID 再开始。需要先看停止原因，再由你决定是否开新的一轮。

## 结果应该怎样理解

这轮保留既定的“可见文本历史”模式：第二轮能看到上一轮题目和回答，但不回传各厂商专有的隐藏推理状态。因此它测的是这一种固定使用方式，不能宣称代表各模型原生多轮能力的最高水平。

参数没有为了压分而改动：

| 厂商 | 推理／采样设置 | 输出限制 |
| --- | --- | --- |
| Gemini | medium；采样参数未指定，沿用服务默认值 | 8,192，含思考和回答 |
| Grok | high；temperature 0.7、top-p 0.95 | 8,192 个可见输出 token，不限制同样数量的思考 token |
| MiniMax | adaptive；M3.1 Flash 显式设 max；服务固定为 1／0.95 | 8,192 个生成 completion token |

同样写 8,192，含义并不相同，所以不是等算力比较。返回被截断时按技术故障停机，不把临床能力记成零分；也不会看见结果后悄悄提高限制。模型别名及省略参数的默认值可能变化，复现性有限。

参数依据已核对：[Gemini](https://ai.google.dev/gemini-api/docs/thinking)、[Grok](https://docs.x.ai/developers/model-capabilities/text/best-practices)、[MiniMax](https://platform.minimax.io/docs/api-reference/text-chat-openai)。Grok 的文档建议回传加密推理状态；我们在这里明确记录与本轮固定模式的区别。

传输层只连接三家的固定 HTTPS 域名，验证证书和主机名，不跟随重定向、不自动使用代理、不启用工具或重试。单次 socket 超时为 900 秒，读取间检查 1,800 秒的总耗时界限；阻塞读取可能让检查延后。请求正文最多 1 MiB；回复最多保留 8 MiB 加一个用于发现超限的字节。

## 如何授权，结果放在哪里

查看方案不读取密钥、不联网：

```sh
python3 -m benchmark.live_s41 plan
python3 -m benchmark.live_s41 audit
```

等你明确批准后，再把**实际批准的原话和消息来源**写入本地授权记录。字段模板和运行命令见[操作说明](S41_LIVE_RUN_2026-10-24_EN.md#commands-and-local-delivery)。公开模板故意是未批准状态，不能拿来直接运行；代码也不会代替你生成批准。

授权绑定本轮协议、运行 ID、输出目录、调用上限和费用规则，最长有效期为 24 小时。授权文件只能由当前用户读写。每个授权 ID 在读取密钥或联网之前就被一次性占用，即使接着发现密钥配置错误，也不能复用。每次发下一笔之前还会重新核对协议哈希和有效期。

这是本地操作记录，**不是能自动证明“本人确实批准过”的数字签名**。操作者必须先核对你的真实消息；也不把它包装成能防住恶意本机用户修改文件的安全边界。

本地目录：

- `work/s41-authorizations/`：授权原件及已使用标记。
- `work/s41-runs/<run_id>/capture/`：请求、原始回复、用量和已验证答案。
- 同一运行目录下的 `spending/`：逐笔额度登记和结算。
- `*.progress.json`、`report.json`：进度和最终结果；进程突然退出时可能只有部分日志，不能据此续跑。

密钥仍从环境变量或 `.env.local` 读取，只有通过授权后才读；实际模型名单来自冻结方案，不受本地单模型名称设置覆盖。未完整跑完时命令返回非零退出码。
