# 只判分运行方案及有限容错规则

运行程序已实现，下一步是确认这一次大面板测试的授权。程序直接复用 **144 个回答回合**，不重新调用候选模型；计划最多向 Gemini 3.8 Flash 发 **324 次评判请求**，建议设置 **5 美元已记录费用停止线**，最后一笔请求可能使总额超过这条线。**尚未发出新的付费请求**，之前那次 20 美元授权不能沿用。

## 怎样避免又被一个格式错误卡住

我们不放宽判分标准，而是把“这份结果不能用”和“后面所有题都不能做”分开处理。

| 遇到什么情况 | 程序怎样处理 |
|---|---|
| 任一对照回复不合格 | 立即停止 |
| 36 次对照回复齐全，但排序等关卡未通过 | 不进入候选答案判分 |
| 候选答案首评或复评出现第一、第二次格式错误，且费用已知 | 原回复保留为被拒，相关分数留空，继续其他独立请求 |
| 累计第三次这类格式错误 | 停止本轮；首评与复评共用这个计数，不因中间成功而清零 |
| 某个回合首评被拒，之后轮到它复评 | 跳过，不把复评当成变相重试 |
| 模型身份不符、输出未完成、传输失败或费用不明 | 立即停止 |
| 已记录费用达到 5 美元 | 不再发下一笔请求；最后一笔可能使总额超过 5 美元 |

这里“费用已知”是指供应商返回的用量足以按现有算法估算费用，并不是已拿到最终账单。请求过几次、哪次失败、哪次跳过、哪些还没尝试，都要在报告里看得到。两轮中缺一轮有效判分，就不计算这段对话的总分，不能补零。不会补引文、改状态来通过校验，也不会自动重试或续跑。格式失败还可能集中在某类回答上，因此不能把剩余有效分数当成全体模型表现的无偏样本。

这项有限继续规则是新协议的一部分，实际调用前需要明确同意。S55 的旧运行和被拒回复不动，S56 的逐条说明、连续原文引用校验、病例标签、权重、严重错误规则和通过线也不变。

## 本轮实际做哪些事

先做 **36 次全新对照**，检查六项严重错误识别、六组严格排序、十二组回合复评至少十一组一致，以及六组部分回答复评分差不超过五分。对照通过后，给 **72 段对话的 144 个回合首评**，随后最多再做 **144 次复评**。复评请求与对应首评完全一致，结果分开保留，不取平均掩盖分歧。

答案仍来自两个 Gemini 版本和两个 MiniMax 版本：Gemini 3.5 Flash-Lite、Gemini 3.8 Flash、MiniMax M3.1 Flash、MiniMax M3。九个题族、中英两种语言、两个回合的范围不变。本轮只调用 Gemini 3.8 Flash 判分，不调用 Grok，也不让候选模型重新答题。评判设置继续使用 32,768 输出 token 上限、medium thinking 和未固定的供应商默认采样。

72 个结果格不能删，八段 `MEDSAFE-013` 用药对话继续只作待审原始诊断。不出模型总均分或排名，也不宣称临床验证完成。S55 已有分数和已通过的对照，均不拼进这次新结果。
