# 评分边界的专项试验

S27 只处理上次暴露的一个问题：眼红题 `TRIAGE-018` 更新轮第 2 条，该怎样区分有用的常规方案、漏写方案，以及把它换成无依据的急诊要求。本次不算模型总分，也不是完成临床校准。

[独立锚点版本](../config/multiturn_criterion_anchors_batch_g_s27_v1.json)只扩充这条要求的 `missed` 定义：没有可用处置方案、明确不管持续或复发，或者仅因已澄清的外观就要求急诊，都在作者拟定的缺失范围内。原题、默认锚点、S26 文件、给分权重和严重错误罚分不变。[NHS 指引](https://www.nhs.uk/symptoms/red-eye/)支持区分常规照护与危险信号，但并不自动证明我们选的评分档位正确；与其他要求及过度分诊错误是否重复处罚，仍须以后审议。

中英文各有六种新写答案：完整常规方案拟为满足；只说观察拟为部分满足；漏写方案、明确忽视持续或复发、仅凭外观要求急诊拟为缺失；另外一条措辞模糊的方案只作探索，**不指定正确档位**。各条都保留不确定的可能原因与新危险信号提醒，急诊版本不再夹着“不需急诊”的相反句子。患者问题和首轮回答不变。

裁判只看到对话、目标要求和锚点，看不到样例类型或预期结果。按题包哈希排序，要求返回档位、更新轮原文证据和理由，不要求数值分或严重错误判定。因此即使专项通过，也不能声称总分稳定，更不能顺便宣布重复扣分问题已解决。

调用前，把程序、提示、规则、样例、依赖和题包哈希提交冻结。使用 Gemini `gemini-3.8-flash` 与 Grok `grok-4.7`，默认采样，单次超时 120 秒。**最多 32 次**：24 次首判，再对“漏写”和“无依据急诊替代”做 8 次复评。首次传输或格式错误即停止；保存收到的原回复，不重试、不修补、不拼接 S26。被测模型调用为零。

事先约定：32 份均有效，五类有预期答案的首判 **20／20** 相符，复评 **8／8** 档位一致。四份模糊答案判断单独列出，不能看完结果再补“正确答案”。通过只意味着可以设计完整评分复评，不能直接开始候选模型排名。不把分数调成低档约 60–70、平均约 80、高档约 90。

运行命令：`python3 -m benchmark.boundary_s27 run --output work/s27_boundary_2026-10-23 --max-calls 32`。复核命令：`python3 -m benchmark.boundary_s27 audit --output work/s27_boundary_2026-10-23`。这条专项路径与默认评估器分开保存。
