# S40 首轮测试的费用停止线

你已经选定：**首轮以 $55 作为停止线，接受最后一笔请求可能超出**。这不是“总账单绝不超过 $55”的保证，也只确定了首轮的费用规则；没有因此批准发送题目或付费调用。[新策略文件](../config/spending_s40_v1.json)单独记录这次选择，旧实验不改。

## 实际怎样停

[费用监控组件](../benchmark/spending_s40.py)一次只允许一笔请求在途。发出前先核对是不是预定的下一项，并保存尝试记录和请求内容；收到结果并完成记账后，才可能开始下一笔。监控金额使用 Grok 返回的收费，加上 Gemini／MiniMax 按 token 估算的费用，统一用整数单位计算。报告仍把两类金额分开列，不把停止线上的合计叫作最终账单。

累计恰好达到或超过 $55 时，最后一份回答和完整费用都会留下，然后停止。例如此前累计 $54，下一笔记为 $3，系统会保留 $57，而不是把数字截成 $55，也不会再发下一笔。这笔超额目前没有可验证的数值上限。若用量缺失或无法核对，就把费用标为未知并立刻停下；不能当作免费继续跑。技术故障也会停，即使累计金额还很低。

记录之间用哈希串联，绑定请求、结算和前一条记录；未完成的尝试不会消失。组件不允许同时发两笔、跳题、重排、重复结算、复用旧目录或自动续跑。写文件失败后也不能继续请求。本机停止只控制后续动作，不能保证服务商已经取消生成或停止计费。

## 已经验证到哪里

现在已把 S38 的调度、S39 的原始回复留存与记账、这次选定的费用规则接在一起，用模拟连接走通完整的 816 次首轮流程。控制题检查仍在候选模型测试之前；费用到线、金额未知或中断时，都不会再打开下一次连接。导致超线的那份回答照常保留，重复判分仍不混入首轮均分。

**590 项测试全部通过，其中新增 33 项。**没有调用模型、读取密钥、修改账户，也没有新增病例或真实成绩；生产运行入口仍关闭。

## 真正付费测试前还要做什么

[首轮范围记录](../config/first_phase_s40_scope_v1.json)已经列明六款候选、两名裁判、九族开发题、两种语言，以及最多 816 次请求：216 次候选回答、600 次裁判调用，后者包含控制题和重复判分。记录中的付费与数据传输授权仍为“未批准”。候选只接收题目轮次和自己的可见历史回答；裁判另接收相应阶段的标签与说明。确认专用题、西安病历、购买的原始资料和本地密钥不进入基准题目载荷。

下一步完成真实 HTTPS 连接器、生产调度与授权检查，核对实际生成参数，再冻结完整协议并申请一次明确的首轮运行批准。提前停止后不能自动新开一轮、清零预算或重复使用旧授权。之前提过的确认阶段 $35，并没有因为这次首轮选择而获批；确认阶段到时另定规则、另行批准。

如果因为费用到线只跑了一部分，结果就应写成“不完整测试”，保留固定分母下的分数区间，不能只拿跑完的模型和题目重新算一个好看的均分。按既定顺序停下，缺失项可能集中在后面的模型或题型。约 80 的目标仍是固定模型组整体均分，不是改分或删掉缺失项的理由。H130 补充记录这个方法学问题，临床和语言审核继续后置。

开发集保持 125 族／250 个语言版本，另有 3 族／6 个版本的新确认题；获批校准集和隐藏 Gold 都为零。MiniMax 仍用 M3 和正式版 M3.1 Flash，S26–S39 冻结文件保留原样。运行 `python3 -m benchmark.spending_s40` 可检查[审计摘要](../data/audit/s40_threshold_summary.json)，全量测试命令为 `python3 -m unittest discover -s tests -q`。
