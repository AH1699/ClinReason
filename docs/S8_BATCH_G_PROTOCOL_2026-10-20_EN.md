## What is now executable offline

- [Exact-case provisional anchors](../config/multiturn_criterion_anchors_batch_g_v1.json) define met, partial, missed and acceptable-equivalent boundaries for all **24 turn requirements** (four families × two turns × three requirements). Each family binds both language variants to their exact content hashes, a primary public source, an explicit critical-error boundary and a later human-review question. EN-written anchors apply provisionally to both languages; structural parity is not meaning equivalence.
- [Eight paired-language contrast probes](../data/multiturn/batch_g_contrasts_v1.json) provide an initial answer and strong, partial and deliberately unsafe update answers for each variant: **24 controlled update answers**. The unsafe answer targets the configured update error, including over-escalation on red-eye appearance or local rash, antibiotic overtreatment from mucus color, and antibiotic/emergency overtreatment from a culture flag. The [offline validator](../benchmark/batch_g_contrasts.py) rejects changed case hashes, unknown error IDs, incomplete language coverage and empty/duplicate fixtures. It cannot verify the medical truth or that an AI judge will rank strong > partial > unsafe.
- [Batch-G pilot roster](../config/model_matrix_batch_g_v1.json) selects precisely these eight variants and the same predeclared three candidate/two-judge model IDs as batch F. A full matrix preview is **48 candidate + 48 judge = 96 API calls**; this is a call count, not a cost cap or authorization to publish a ranking.
- [Bilingual candidate instruction v2](../config/candidate_prompt_bilingual_v2.txt) explicitly asks the model to answer each turn in the user's language, permitting customary medical terms. The previous [default instruction](../config/candidate_prompt.txt) remains unchanged. `model-matrix`, `judge-saved-matrix-answer` and `assemble-model-matrix` accept `--candidate-prompt`; saved manifests/reports bind instruction hashes, and a dry-run plan with the override prints that hash. Recovery/assembly must name the same prompt version as their source artifacts. Never compare F and G candidate scores as if the prompt protocol were identical.
- The [separate offline language audit](../benchmark/answer_language_audit.py) now accepts `--candidate-prompt` and checks each saved answer's sidecar manifest against that instruction hash and case revision. It flags only obvious English-script answers to Chinese cases or vice versa, with **no language score and no change to the clinical score**. An unflagged answer is not a pass: mixed language, fluency, interpretation and EN/ZH clinical equivalence need bilingual review. Historical F outputs lacked the v2 instruction and must not be reported as v2-adherent.

The anchors and contrast wording were checked against the [NHS red-eye page](https://www.nhs.uk/symptoms/red-eye/), [Moorfields patient guidance](https://www.moorfields.nhs.uk/ae/patient-guides/subconjunctival-haemorrhage), [AAAAI latex-reaction distinctions](https://www.aaaai.org/tools-for-the-public/conditions-library/allergies/latex-allergy), [CDC adult outpatient antibiotic guidance](https://www.cdc.gov/antibiotic-use/hcp/clinical-care/adult-outpatient.html), and [IDSA asymptomatic-bacteriuria guidance](https://www.idsociety.org/practice-guideline/asymptomatic-bacteriuria). Those US/UK sources inform synthetic answer boundaries; they do **not** validate patient-specific dispositions or a global care pathway. The [OpenAI evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices) motivated task-specific fixtures, exact protocol logging and a later human-calibration gate; this project uses its own local evaluator, not OpenAI's hosted Evals platform.
