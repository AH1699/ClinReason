# S22 独立授权裁判面板——2026-10-22 前瞻方案

S22 是**新的仅开发阶段尝试**，不是恢复或重试已中止的 S21 目录。[S21 记录](S21_EVIDENCE_EXPLICIT_JUDGE_PROTOCOL_2026-10-22_ZH.md)保留了一次是否送达／计费未知的 Gemini 请求尝试，且没有可核实判断；不能从审计轨迹删除。负责人授权这次新运行最多**额外 32 次裁判调用**，不调用候选模型。提示、案例、英中译文、作者编写的答案对照、锚点、量表、裁判名单及 12 个准确题包哈希均与冻结的 S21 输入相同。[S22 方案](../config/judge_evidence_panel_s22_v1.json)绑定不变的 S21 来源及执行程序文件，并绑定离线计划哈希。[外围程序](../benchmark/judge_evidence_panel_s22.py)另行记录 S22 授权、无密钥连通性与完成证据；内部 S21 格式文件仅是实现产物，不能与 S21 观察合并。

**每个**计分阶段之前，必须在相同进程及联网环境中向两家服务商主机发送不带密钥的 HEAD 请求并收到 HTTP 回应。预检不发送 API 密钥或案例内容。任何 HTTP 回应（包括 API 根路径的 404）只证明主机可达，不能证明凭证、模型可用或计分成功。DNS 或传输失败则在任何计分请求前停止。首轮最多新增 24 次裁判调用；只有完整、独立复核通过的首轮才能进行八次同包部分答案重复。禁止自动重试。任何失败或送达不确定的计分调用都终止这次新运行；不得复用不完整目录或与以后运行合并。因缺少服务商账单遥测，无法设定金额上限。

主要观察项仍是证据标签格式及部分答案的准确分数／条件状态／严重错误／通过标记重复性；预设不安全错误检出、优秀／部分／不安全排序、满分聚集及双语差异是次要描述性检查。格式检查不能验证临床理由；作者答案和锚点不是 Gold。现行数值规则、历史结果和 S20 比较暂缓均不改。该面板不能证明临床校准、模型质量／排名、双语等价或期望的低档约 60–70／中档约 80／高档约 90 分段。以后仍必须有合格临床、双语和方法学审核。

执行顺序：任何计分调用前先提交本方案；离线执行 `python3 -m benchmark.judge_evidence_panel_s22 plan`；在允许联网的环境用全新的被忽略 `work/` 输出目录及 `--max-api-calls 24` 执行 `run-first`；运行 `audit-first`；只有它通过才用 `--max-api-calls 8` 执行 `run-repeat`，最后执行 `audit`。原始回答与本地密钥均被 Git 忽略；仅在逐案例／语言／裁判分列并注明局限后发布谨慎的开发诊断。公开开发集仍 **115 个双语题族／230 个版本**，获批校准及隐藏 Gold **0／0**。
