# 医疗/诊所评测章程 v0.1 — 中文

状态：**待审批草案**  
日期：2026-10-06  
适用范围：SectorBench Healthcare/Clinics Alpha

本章程规定评测可以衡量什么，以及评测结果可以如何使用。它是评测治理文件，不构成医疗建议，也不授权任何临床部署。

## 1. 使命

评估通用或医疗类大模型在合成诊所工作流中，能否给出安全、正确、清晰的回答。评测优先识别可能造成伤害的失败，而不是优化排行榜；其用途是受控的内部模型选择、研究以及自动评审校准。

## 2. 预期用途

Alpha 阶段允许：

- 内部研究和工程评测；
- 在固定合成案例上比较候选模型行为；
- 用独立专家标签校准自动评审模型；
- 研究英文与简体中文表现的一致性；
- 开发案例编写、审核、评分和审计方法。

任何对外分数声明都必须满足第 10 节的发布门槛。Alpha 结果必须标记为 `unvalidated`。

## 3. 禁止及排除用途

不得用本评测：

- 提供医疗建议、诊断、治疗或针对真实患者的分诊；
- 在真实临床工作流中部署或批准模型；
- 替代临床、法律、隐私、安全或监管审查；
- 对临床人员、患者、医疗机构或人口群体进行排名；
- 使用、上传或保留受保护健康信息；
- 将有限工作流中的成绩宣称为广泛临床能力；
- 在专家验证与校准完成前发布模型排名。

## 4. 初始范围

| 项目 | Alpha 决定 |
|---|---|
| 行业 | 医疗健康 |
| 工作流 | 门诊/诊所信息辅助 |
| 数据 | 仅合成数据；不含 PHI/PII |
| 评测层 | 不依赖司法辖区的全球核心；各地扩展包作为独立模块 |
| 语言 | 英文（`en`）和简体中文书写系统（`zh-Hans`） |
| 评测单位 | 双语案例族；每种语言一个独立审核的变体 |
| 类别 | 临床推理、分诊、用药安全、患者沟通、临床知识、对抗/安全 |
| 评分 | 0–4 绝对评分加关键错误门控；成对排名仅作补充 |
| 使用阶段 | 仅研究/评测；不得用于临床 |

Alpha 不包括：多模态输入、EHR 集成、自主执行、工具调用、纵向照护、模型训练和真实患者记录。

## 5. 案例进入验证前必须确定的事项

全球核心的司法辖区决定已经确定：案例使用 `benchmark_layer=global_core` 和 `jurisdiction=global_core`。以下剩余事项未解决前，案例不得从 `draft` 升级：

1. **目标用户：**明确题目模拟工作人员、患者或两类工作流，并分别标记。
2. **人群范围：**明确是否仅限成人；儿科或妊娠相关范围须配置合格审核者。
3. **全球中文风格：**批准自然的简体中文术语，同时避免默认某一国家医疗系统。
4. **权威来源：**批准全球来源层级、时效窗口和更新周期。
5. **审核者资质：**批准专业范围匹配和利益冲突披露规则。
6. **发布阈值：**批准一致性、关键错误敏感度、样本量和不确定性要求。
7. **首批司法辖区扩展包：**仅在目标市场和合格本地审核资源明确后选择。

评测负责人记录决定；临床安全负责人批准第 2、4、5、6 项；语言负责人批准第 3 项。开始地区扩展包时，由对应负责人批准第 7 项。

## 6. 双语设计规则

一个案例族表示同一个临床构念。英文和简体中文（`zh-Hans`）变体必须保持相同事实、任务、风险等级、适用维度和关键错误政策。翻译不要求逐字对应，但本地化不得改变难度或预期临床行为。全球核心措辞必须避免特定国家的急救号码、机构、法规和就医路径。每个语言变体都须分别接受语言和临床审核。同一案例族必须完整保留在开发集或 Gold Set 的同一分区，防止泄漏。

## 7. 数据与隐私规则

- 仅使用合成内容，或经隐私负责人批准的完全去标识内容；Alpha 默认仅合成数据。
- 不得包含姓名、出生日期、地址、病历号、联系方式或从真实病历复制的自由文本。
- 凭据只存放在环境变量中，不得写入案例、日志、SQLite 或版本清单。
- 在真实 API 运行前，必须批准原始供应商输出的保留期限和访问策略。
- 发现疑似敏感内容时，应立即隔离，在复核前不得进入任何运行。

## 8. 角色与决策权

| 角色 | 责任 |
|---|---|
| 评测负责人 | 范围、版本、发布清单和变更控制 |
| 临床安全负责人 | 临床范围、安全分类、审核资格和最终安全决定 |
| 案例作者 | 起草和修改案例；不得独立批准自己编写的案例 |
| 独立临床审核者 | 验证临床事实、参考行为、要求、错误和来源 |
| 语言审核者 | 验证含义、术语、可理解性和跨语言等价性 |
| 裁决者 | 解决有记录的分歧；不得删除原始审核记录 |
| 隐私/安全负责人 | 数据规则、供应商审查、保留、密钥和事件响应 |
| 发布批准者 | 核验所有门槛并签署发布记录 |

项目早期同一人可以兼任多个角色，但发布案例的作者和独立批准者必须分开。

## 9. 变更控制

凡修改题目、参考答案、关键要求、关键错误、语言含义或来源解释，都必须提升案例版本，并重新完成受影响的审核。分类体系、权重、门控、预期用途或不兼容模式变化需要提升评测主版本。已完成的运行记录不可修改。

## 10. Alpha 与发布门槛

### 进入 Alpha

- 剩余章程决策已有记录；
- 六个类别共起草 30–50 个全球核心案例族；
- 两种语言变体均通过开发模式验证；
- 不含真实患者数据；
- 审核分工已有记录。

### 升级为临床已验证

- 案例具有权威来源和生效日期；
- 独立合格审核者批准临床内容；
- 语言审核者批准每个本地化变体；
- 关键要求可观察，关键错误已预先定义；
- 所有必须修改项均已解决并留痕。

### 升级为 Gold/可发布

- 双重临床审核和裁决完成；
- 整个案例族只进入一个数据分区；
- 自动评审在隐藏标签上达到校准阈值；
- 不存在未解决的 3 级错误争议；
- 隐私、安全和发布检查表已签署；
- 任何结果都同时公布已知限制和不确定性。
