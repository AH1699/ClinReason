# F 批次有限实时试验 — 2026-10-19 预先记录

本试验仅用于**公开开发集诊断**，不是评分校准、临床验证、模型排名，也不测试前瞻性校准或隐藏集。以下协议在查看任何 F 批次模型回答**之前**写定。与潜在合作伙伴讨论期间专家审核推迟；题目要求、锚点及译文都只是暂定草案。不能据此作出临床声明，或声称达到约 60–70／80／90 的期望分段。

## 固定题目与调用界限

- 题目：[患者 F 批次](../data/multiturn/batch_f_cases.json)新增的四族，分别使用英文与简体中文，共八个版本，顺序固定于[`config/model_matrix_batch_f_v1.json`](../config/model_matrix_batch_f_v1.json)。不发送 Alpha、专业、前瞻性校准或隐藏草案。
- 候选模型：Gemini 3.5 Flash-Lite、Grok 4.6、MiniMax M2.7；**没有**预先指定质量档位。Gemini 3.8 Flash 与 Grok 4.7 分别评审每份回答。同公司候选／评审配对会标记，不混成所谓真值。
- [绑定准确案例版本的暂定逐项锚点](../config/multiturn_criterion_anchors_batch_f_v1.json)列出两轮满足／部分／未满足界限、可接受替代说法、来源局限及待审问题。英文锚点也用于配对中文题；语言等值性尚未经审核。
- 现有候选提示、逐项 v2 评审提示及数值量表不变。每个版本调用候选两次、评审两次。计划最多 **96 次逻辑调用**（候选 48、评审 48），每个候选**32 次**。调用次数不是费用上限；尚无账单遥测。失败或传输是否送达不明时不会自动重试。

先离线预览计划，再对每个候选仅运行**一道英文题**作四调用连通／协议测试；任一合同、服务或来源绑定失败就暂停。若三个都通过，其余七个准确版本分别保存在新目录，之后用同一固定名册和锚点离线组装三份报告。不得悄悄重试失败题或复用送达情况不明的回答。原始回答及评审保留在 Git 忽略的 `work/`；只有去标识化描述记录可提交。

## 预定分析与停止规则

按题目、语言、候选和评审分别检查：满分频率、重大错误与封顶、六项要求状态、首轮安全、后续修正、两评审分数／状态差异、英中成对分差。**至少五分**的差异标记为回答级别复查。两评审不取平均；不报告总排名、模型档位或分段拟合。公开来源链接与两个 AI 评审意见一致都不能证明标签正确。

若评审违反回答证据合同、把已配置的三级不安全答案判为通过，或两评审在严重安全错误上意见不一，应隔离该题的比较解释，并记录原回答供日后合格人员审核。看过结果后不得悄悄更改权重、题目、提示或锚点并仍称同一协议；须记录新版本并重新测试所有候选。正式校准前仍需独立临床及双语裁决。[OpenAI 官方评测指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)同样建议及早开展范围明确的测试，并以人工反馈校准自动评分。

试验之后只判断新题能否暴露不同失败模式，还是继续出现满分聚集及评审宽松。这两种结果都可帮助设计**下一批**低紧急度／降级对照题，却不能成为向约 80 分调曲线的理由。
