# S22 separately authorized judge panel — prospective protocol, 2026-10-22

S22 is a **new development-only attempt**, not a resume or retry of the aborted S21 directory. The [S21 record](S21_EVIDENCE_EXPLICIT_JUDGE_PROTOCOL_2026-10-22_EN.md) has one attempted Gemini request of unknown delivery/billing and no verified judgment; it remains in the audit trail. The owner authorized up to **32 additional judge calls** for this new run. No candidate model is called. The prompt, cases, EN/ZH translations, author-written answer controls, anchors, rubric, judge roster and exact 12 packet hashes are identical to the frozen S21 inputs. The [S22 policy](../config/judge_evidence_panel_s22_v1.json) binds the unchanged S21 source and runner files plus the offline plan hash. Its [wrapper](../benchmark/judge_evidence_panel_s22.py) records separate S22 authorization, keyless connectivity and completion evidence; internal S21-format files are implementation artifacts, not pooled S21 observations.

Before *each* scored stage, the same process and network environment must obtain HTTP responses to keyless HEAD requests at both provider hosts. No API key or case content is sent in this preflight. Any HTTP response (including 404 at an API root) proves host reachability only, not valid credentials, model availability or successful scoring. DNS or transport failure stops before any scored request. The first stage is capped at 24 new judge calls; only a complete independently re-audited first stage permits the eight exact-packet partial-answer repeats. Automatic retries are disabled. Any failed or ambiguous scored call stops the new run; do not reuse a partially completed directory or pool it with a later run. Monetary cost is not capped because provider billing telemetry is unavailable.

The primary observations remain evidence-marker format and exact partial-answer score/status/error/pass repeatability. Named unsafe-error detection, safe/partial/unsafe ordering, ceilings and bilingual differences are secondary, descriptive checks. The linter cannot validate a clinical rationale; author answers and anchors are not Gold. The numeric scoring contract, historical results and S20 comparison hold remain untouched. This panel cannot establish clinical calibration, model quality/rankings, cross-language equivalence or the desired ~60–70/~80/~90 performance bands. Qualified clinical, bilingual and methods review remains mandatory later.

Execution sequence: commit this protocol before scored calls; run `python3 -m benchmark.judge_evidence_panel_s22 plan` offline; execute `run-first` with a fresh ignored `work/` output directory and `--max-api-calls 24` in a network-enabled environment; run `audit-first`; only if it succeeds, run `run-repeat` with `--max-api-calls 8` and then `audit`. Raw responses and local keys stay ignored; publish only careful aggregate development diagnostics with case/language/judge breakdowns. Public development stays **115 bilingual families / 230 variants**, approved calibration and hidden Gold **0/0**.
