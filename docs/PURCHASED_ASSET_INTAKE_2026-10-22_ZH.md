# 原始病例怎么交，题目由我们来做

这份说明给采购和数据整理同事用。**你们只需交原始、可关联的资料；脱敏复核、读扫描件、编题、写参考答案、查证据、做中英文版本，都由 ClinReason 项目组负责。** 首批希望收到约 30 个不同的就诊事件。这是试运行目标，不是要求凑满 30 题；资料不完整时，少而完整比多而零散更有用。

## 请优先找这样的资料

一个好的病例包，能回答“当时医生或患者知道什么，后来又发生了什么”。最好能看到初诊、化验或影像、用药变化、后续病程和结局。我们尤其需要病情会变化、检查结果不一致、药物和合并症相互影响、需要补问信息或调整处理级别的过程。不要只按罕见病名挑资料；普通且可合理观察的病例也需要，它们能防止基准只会考“立刻急诊”。

**按人和事件打包，不按 PDF 页数打包。** 同一位患者的一次住院即使有几十张报告，也先算一个事件。如果同一人有多次就诊，请保留这些记录之间的关联和先后顺序。我们收到后再决定其中哪一刻适合出题、属于分诊／用药安全／诊断推理中的哪类，以及能否形成双轮题；不需要数据组预先分类。

原始文件保持收到时的样子即可：电子病历导出的 CSV、JSON、FHIR，或 PDF、图片扫描件都可以。有结构化原文就不要特意转成图片。请尽量保留化验数值和单位、参考范围、药名和剂量，以及出院或随访结局。不要把许多文件拼成一张巨大的 PDF，也不要为我们改写成“案例题”。

## 数据组实际要交什么

最简单的交付方式是每个事件一个子文件夹，再给一张文件清单：

```text
raw_batch_001/
  README.md                 可选：说明来源格式、缩写、缺失资料
  file_index.csv            必需：每个文件一行，说明它属于哪个事件
  records/
    EP001/                  第一个事件的原始文件
    EP002/                  第二个事件的原始文件
    ...
```

`file_index.csv` 建议只填七列：`episode_id, file_path, document_type, language, sequence_or_relative_time, deid_status, notes`。也就是：自建事件编号、文件位置、是什么报告、语言、先后次序或相对时间、原资料是否声称已去标识化（`yes/no/unknown`）、需要提醒我们的事项。清单和文本请用 UTF-8。文件夹内若本来就是几张数据表，只要在清单或 `README.md` 说清患者和就诊之间怎么关联，不必改造成 PDF。**清单不要使用姓名、原病历号或医院内部号作为事件编号。**

例如一行可以写：`EP001,records/EP001/admission.pdf,入院记录,zh-Hans,第1份,unknown,`。这行只告诉我们文件是什么，不写患者姓名，也不写“正确答案”。

除此之外，不要求数据组提供答案、评分标签、英文翻译、指南摘录、人工 OCR 或脱敏报告。如果随原始资料附带这些东西，可以一并保留作为参考，但请和原始病历分开；项目组会自行核对，不会直接拿来当标准答案。

交接请走约定的安全本地渠道。不要把原病历贴到聊天、邮件、Git 仓库或任何模型 API 里。已经脱敏的资料也请在清单上注明来源声称的状态；**我们仍会复核**。

## 收到资料后，项目组怎么把它变成题

1. **先理清“有多少例”。** 逐个文件登记、查重复，确认同一人的记录没有散到不同病例包，排好时间线。缺关键记录就标记，不靠猜。
2. **由我们做隐私检查和必要处理。** 在本地检查可提取文字、扫描件 OCR、图片和文件元数据；处理姓名、号码、精确日期、地点及可能拼出身份的特殊细节。保留临床上有用的相对间隔，例如“症状出现后两天”。处理后再复查。若仍可能识别个人，先隔离，不送外部模型，也不写入公开题库。自动遮盖并不等于已经完成合格的匿名化判断；需要时再走专业隐私审核。
3. **还原病程。** 把症状、重要阴性、既往病史、药物、生命体征、检查、处置和结局整理成结构化时间线。保留原单位和来源页码。会影响答案的 OCR 内容人工复核。
4. **选择一个提问时点。** 题目只呈现当时已知的信息；后来的病理、确诊和结局只用于核查，不能提前泄漏。我们另写全新的提问和草稿答案：可接受的回答、必须做到的具体事项、严重错误、合理替代判断和不确定性。现实病历中的处置不自动等于正确答案。
5. **查证并做双语版本。** 每条答案要求另找现行指南或药品资料核对，记录适用人群和局限；再编写事实和风险一致的中英文题。运行格式、重复、难度和泄漏检查。临床、语言和方法学审核可以在后续合作阶段完成；在那以前一律标记为草稿，不算 Gold。

原始资料、OCR 文本和脱敏后的中间文件只放在受限且 Git 忽略的本地位置。真正进入基准库的只能是完成隐私检查后**重新编写**的题目、独立保存的答案标签及来源记录，不能把原病历文字直接复制到公开 Alpha。单轮、双轮题的最终结构由我们根据[项目案例格式](../schemas/case.schema.json)和[双轮格式](../schemas/multiturn-pilot.schema.json)转换，数据组不用适配代码。为避免泄漏，同一事件的所有语言版本和变体始终放在同一个数据分组。

## 现有三个目录先怎么用

- **`ClinicalDataXiAn`：先拿它做处理流程试点。** 50 份图像型 PDF、共 90 页，目前看来是同一次住院，不是 50 例。先按入院、病程、检验／其他报告、手术、病理、出院的顺序关联和去重，再在本地做 OCR 与隐私复核。通过后才考虑从某一时点编题。
- **`2.Usmle world step2`：用来研究题型和覆盖缺口，暂不直接搬题。** 68 份 PDF，约 57,687 页。有病例式题目，也有主题索引；公开流传过的题目可能已被被测模型见过。若采用其中的知识点，也要去重、重新设计情境、独立核查答案。
- **`4.Usmle world step1`：排在后面。** 283 份 PDF 和 8 个压缩包，约 51,166 PDF 页；更适合查基础知识覆盖，不是当前患者决策题的主要来源。

这次只是快速盘点，没有把任何已购内容转成案例，也没有调用模型。`purchasedAssets/` 继续不进 Git。去标识化不能只看姓名栏是否为空：自由文本、日期和图片同样可能留下线索；处理方法可参考 [HHS 去标识化技术指南](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html)，涉及中国个人健康资料时还要注意[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。现有[S23 评分边界暂缓](S23_OFFLINE_SCORING_BOUNDARIES_2026-10-22_ZH.md)不受这次资料接收流程影响。
