# Focused scoring boundary experiment

S27 tests the single uncovered boundary found in S26: `TRIAGE-018`, update requirement 2. This is a focused test of whether two judges apply a provisional criterion consistently—not a new model benchmark, numeric scoring calibration or clinical approval.

The [separate anchor version](../config/multiturn_criterion_anchors_batch_g_s27_v1.json) changes only that criterion's `missed` definition. It explicitly includes an absent usable plan, dismissal of persistence/recurrence, and replacement with emergency care solely for the clarified appearance. It does not change cases, default anchors, S26 files, numeric credit, weights or critical-error penalties. The medical distinction is informed by [NHS red-eye guidance](https://www.nhs.uk/symptoms/red-eye/); the exact criterion classifications remain author hypotheses. Overlap with other requirements and the overtriage penalty still needs later review before numerical adoption.

Six original answer variants are authored in each language: routine plan (`met`), limited observation (`partial`), omitted plan (`missed`), explicit dismissal (`missed`), mandatory appearance-only emergency substitution (`missed`), and ambiguous plan wording (exploratory, **no expected status**). Each retains an uncertain possible explanation and a new-red-flag safety net. The emergency variant therefore does not retain the contradictory statement that emergency care is unnecessary. Initial answers and patient turns are unchanged. English/Chinese equivalence remains unreviewed.

The judge sees the conversation and target requirement with anchors, not fixture profiles or expected statuses. Packets are ordered by hash. The schema asks only for status, literal update evidence and rationale. No numerical score or critical-error judgment is requested, so success cannot establish total-score repeatability or resolve duplicate deductions.

Freeze the runner, instruction, policy, anchors, fixtures, dependencies and exact packet hashes in Git before calls. Judges: Gemini `gemini-3.8-flash` and Grok `grok-4.7`, default sampling, 120-second timeout. **Maximum 32 calls:** 24 first judgments plus 8 repeats of omission/emergency-substitution packets. Stop on the first transport/validation failure, save all received responses, make no retry or repair, and never pool with S26. Candidate calls: **0**.

Predeclared gate: all 32 valid; **20/20** first judgments for the five non-ambiguous variants match their author status; **8/8** repeated statuses match. The four ambiguous judgments are reported separately and cannot be assigned an expected answer after results. The gate permits only designing a full-scoring repeat; it never permits candidate-model comparison by itself. Report incomplete cells separately, model identities, mismatches, repeat pairs and ambiguities. No score rescaling toward the desired lower ~60–70 / average ~80 / premium ~90 bands.

Run `python3 -m benchmark.boundary_s27 run --output work/s27_boundary_2026-10-23 --max-calls 32`. Re-audit with `python3 -m benchmark.boundary_s27 audit --output work/s27_boundary_2026-10-23`. The focused code and output are separate from the default evaluator.
